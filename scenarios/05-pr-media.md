# 3E｜PR / 媒体 / 发布会（深度专业包）

**先读案例包**：`../references/scenario-case-packs/05-pr-media-cases.md`

## 适用题型
新品发布会、媒体沟通、企业传播、技术发布、行业议题、媒体日、采访、新闻稿/Press Kit、展会媒体传播。

## 最少需要的输入
要发布的事实、目标受众/地区、可公开数据、可采访人员、Demo/素材、时间、合规边界、目标媒体或行业。

## A｜新闻价值地图 + 媒体分层
```text
读取 PR 案例包和题目事实，先做【新闻价值地图】。

从以下方向判断哪些真正成立：
公司战略变化、行业趋势、技术/产品突破、用户影响、可验证数据、当地市场意义、人物故事、设计/体验、合作生态、公共议题。

不要把公司想讲的每句话都当新闻点。对每个候选新闻点评分：新鲜度、重要性、独特性、证据强度、目标媒体相关性、可解释性、潜在质疑。

针对【大众 / 商业财经 / 科技 / 行业垂直 / 设计生活方式 / 本地媒体】分别输出：
- 读者真正关心的问题；
- 最强标题事实；
- 需要的证据；
- 最适合采访谁；
- 最可能追问的问题。

最终推荐 1 个主叙事 + 2–4 个媒体切口。

成功标准：每个媒体切口都包含可核验的新信息或观点，不依赖“领先、创新、重磅”等自我评价。
```

## B｜Message House + Media Kit + 发言人体系
```text
建立媒体沟通【Message House】：
核心结论 / 3 个支撑信息 / 每个支撑的证据 / 对行业和用户意味着什么 / 需要保留的限定条件。

然后生成 Media Kit 清单：
- 80–120 字事实摘要；
- 5–8 条可直接引用的事实点；
- 关键数据及来源；
- 产品/技术/人物/空间图片；
- Demo 视频或 B-roll；
- 时间线；
- 10–15 个 Q&A；
- 技术词汇表；
- 易误解表达及准确版本；
- 联系人与会后补充机制。

设计发言人分工：高管讲战略和判断，产品/研发讲机制与边界，本地/业务负责人讲市场与执行，用户/合作伙伴在适合时提供第三方视角。

为每个发言人写：3 个核心信息、3 个不能越界的点、5 个尖锐问题和建议回答结构。

成功标准：媒体即使只使用资料包，也能写出事实准确、有行业意义的报道。
```

## C｜发布会 / 媒体体验旅程
```text
从记者和 creator 的完整工作旅程设计活动：
为什么值得来 → 到场后 5 分钟内理解什么 → 哪个 Demo 最能证明新闻点 → 谁讲什么 → 什么时候有采访 → 如何快速拿到素材 → 离场后怎样继续获得信息。

输出：
1）议程与每段的“新闻任务”；
2）空间/展区/体验设计；
3）最值得拍摄的 3–5 个视觉节点；
4）媒体分组与采访安排；
5）直播/社媒与现场关系；
6）资料发放和会后 follow-up；
7）技术故障、发言超时、临时质疑等备用方案。

每一个现场装置、视频和演讲段落都要对应一个报道信息点，并尽量让记者通过亲自体验获得证据。

成功标准：记者的时间被尊重；采访、拍摄、事实确认和素材获取都顺畅；现场体验能直接支持报道角度。
```

## D｜Earned Media 运营 + 媒体关系资产
```text
设计四阶段媒体运营：
会前预沟通 / embargo 或预览（如适用） → 发布日 → 会后深度 → 长尾行业议题。

建立媒体名单逻辑：Tier 1 / 垂直核心 / 本地 / creator / 分析师，各自的价值、关系目标、pitch 内容和 follow-up 频率。

建立媒体问答与快速响应机制：哪些问题可以现场回答，哪些需要研发/法务确认，承诺多久补充。

衡量不要只看发稿量。至少看：
目标媒体覆盖、核心信息带出率、事实准确率、独立观点/引用、正负面、Share of Voice、搜索结果、后续采访、媒体关系深度和内容二次引用。

成功标准：活动结束后仍有可持续媒体议题和关系资产，而非只完成一轮新闻稿分发。
```

## E｜编辑视角验收
```text
最后模拟三名目标媒体编辑：商业财经、科技产品、生活方式。

每人只基于当前资料写：
- 一个可能采用的标题；
- 5 行报道摘要；
- 还缺的事实；
- 最想追问的一题；
- 哪一处最像品牌宣传、需要补证据或换表达。

根据结果修订 Media Kit、发言人 Q&A 和现场安排。

最终产出应包含：新闻价值地图、媒体分层、Message House、Media Kit、Q&A、发布会旅程、媒体运营时间轴、指标和风险处理。
```

## 注意避免
- 每个媒体都发同一封 pitch；
- 新闻稿只有品牌形容词，缺少可引用事实；
- 高管、研发、市场说完全相同的话；
- 发布会大部分时间被 PPT 占用，Demo/采访时间不足；
- 用“发稿量”代替真正媒体影响；
- 对未确认技术/安全问题过度承诺。
