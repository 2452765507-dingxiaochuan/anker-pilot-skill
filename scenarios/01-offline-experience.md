# 3A｜线下体验空间 / 门店 / 品牌体验（深度专业包）

**先读案例包**：`../references/scenario-case-packs/01-offline-experience-cases.md`

## 适用题型
旗舰店、体验中心、品牌空间、快闪、展台/展厅运营、客户体验空间、零售创新、O2O 体验。

## 最少需要的输入
地点/面积/周期/目标人群/产品范围/预算或资源边界/最终交付形式。缺失时可先给假设区间与验证清单。

## A｜案例迁移 + 空间角色判断
```text
请先读取线下体验空间案例素材包，并结合本题材料做一次【案例迁移分析】。

不要复述案例历史。请做一张表：案例 / 最值得借鉴的机制 / 它解决的用户或业务问题 / 迁移到本题的具体方式 / 可能不适用的条件。

随后判断本项目空间承担的角色，并明确主次：
销售与转化、品牌体验、技术教育、会员关系、媒体内容、用户研究、售后服务、社区活动。

输出：
1）一句话空间任务；
2）主角色 + 2 个次角色；
3）目标人群来这里要完成的真实任务【Jobs to be Done】；
4）网上购物或普通卖场无法完全替代的体验价值；
5）本空间最值得形成的长期资产。

成功标准：看完这一页，业务负责人应该能判断“为什么值得做这个空间，以及空间最优先服务什么”。
```

## B｜体验叙事 + 动线 + 分区架构
```text
现在把空间任务发展成完整体验架构。

先给 2–3 种分区逻辑，例如：生活场景、用户任务、Anker for You / Anker for Home、技术能力、产品类别或混合方式。逐一比较信息清晰度、体验自然度、未来更新能力和运营难度，明确推荐一套。

设计从“看到门店”到“离店后继续关系”的完整用户旅程：
吸引 → 进入 → 快速理解 → 深度体验 → 证明价值 → 咨询/选择 → 购买或留资 → 分享 → 后续服务。

对每个核心区域写清：
- 这个区域回答用户什么问题；
- 主要产品/内容；
- 用户动作；
- 员工动作；
- 最关键的可感知结果；
- 进入下一步的自然引导。

补充空间节奏：强吸引点、停留点、安静理解区、社交/拍摄点、咨询区、服务区之间如何避免互相干扰。

成功标准：用户不看说明书也能理解路线；每个区域都有明确任务；多品类之间形成关系而非堆货。
```

## C｜Demo 设计 + 技术证明 + 内容生产
```text
为每个核心产品/技术设计一个真正可以运行的体验脚本【Demo Script】。

每个 Demo 按以下格式：
1）用户先看到/遇到什么真实问题；
2）用户亲手做什么；
3）产品发生什么变化；
4）结果如何被看见、听见、比较或量化；
5）体验顾问如何用 20 秒解释；
6）有哪些限定条件需要诚实说明；
7）如何自然形成短视频、照片或媒体可拍素材；
8）设备故障/排队时的备用版本。

优先参考 Dyson“技术可证明”、Apple“学习任务”、Samsung 837“兴趣场景”的机制，但最终表达必须适合 Anker 的真实产品。

另外设计 1 个跨品类体验，展示多个设备一起完成一个生活任务，体现 One Anker 的整体价值。

成功标准：核心卖点尽量由体验证明，而不只由员工口头说明；Demo 3 分钟内可完成、易复位、可重复、可维护。
```

## D｜运营系统 + 人员 + 内容日历
```text
把空间设计成一个能持续运行 12 个月的系统。

请建立：
【日常】自由体验、固定 Demo、售后/咨询；
【每周】Workshop / 主题体验；
【每月】新品、达人、用户社群、设计/科技话题；
【节点】大促、IFA/CES 后新品、节日、当地文化事件；
【媒体】新品预览、采访、拍摄、行业活动。

设计体验顾问角色：培训内容、开场方式、需求诊断、Demo、跨品类推荐、会员承接、售后交接；同时说明如何避免过度销售压力。

建立内容生产机制：哪些现场事件会持续产出品牌自有内容、KOL 内容、UGC、FAQ、用户洞察。

补充空间更新机制：哪些部分是长期固定资产，哪些模块 4–8 周可以更换，避免半年后失去新鲜感。

成功标准：空间即使没有“开业热度”也有稳定理由让用户、媒体和社区再次回来。
```

## E｜经营闭环 + KPI + 最终交付验收
```text
现在完成空间的经营与验收设计。

建立三层指标：
1）经营：客流、有效体验、体验→咨询、咨询→购买、客单、连带、多品类购买、服务效率；
2）品牌：停留、Demo 完成率、核心信息理解、UGC/媒体、NPS/推荐意愿、品牌搜索；
3）用户资产：会员新增、可触达用户、活动复访、售后满意、社群参与。

没有真实基准时给公式、采集方式和“达到什么趋势就加码/优化/收缩”的判断逻辑，不编目标数。

给 30/90/180 天学习计划：每阶段最需要验证什么，什么结果会改变空间内容、人员配置或活动策略。

最后检查方案是否同时回答：为什么来 / 来了做什么 / 为什么相信 / 如何持续来 / 如何转化 / 如何更新 / 如何衡量。

如果题目要求 HTML，再调用通用交付模块，页面至少清楚呈现：定位、用户旅程、空间架构、核心 Demo、运营日历、指标与阶段路线图。
```

## 注意避免
- 每个区域都是“屏幕 + 展板 + 产品台”；
- 为拍照造景却与产品价值弱相关；
- 把销售、会员、扫码塞进每一步造成体验摩擦；
- 固定重装置太多、更新成本过高；
- 活动很热闹但没有数据、内容和用户关系沉淀。
