# 3H｜技术语言 → 用户语言 / 科技传播（深度专业包）

**先读案例包**：`../references/scenario-case-packs/08-tech-to-human-cases.md`

## 适用题型
AI/芯片/算法/隐私/智能家居/储能/机器人/新材料等复杂技术的用户传播、媒体解释、Demo、详情页、展会讲解、销售工具。

## 最少需要的输入
技术说明、测试条件、与上一代/替代方案的比较、目标用户、真实场景、可公开数据、可演示资产、限制/边界。

## A｜技术事实地图 + 证据等级
```text
先以工程/产品视角建立【技术事实地图】，暂时不做营销表达。

逐项记录：
技术名称 / 解决的技术问题 / 核心机制 / 输入输出 / 与上一代或替代方案的差异 / 可量化结果 / 测试条件 / 限制 / 安全隐私边界 / 来源。

所有“更快、更强、更智能、更安全、领先”等比较都要写清比较对象、场景和测试条件。

把证据分为：官方规格、实验/benchmark、第三方测试、真实用户数据、现场 Demo、工作假设。标出哪些可以公开传播，哪些需要研发/法务确认。

成功标准：技术团队阅读后认为准确；传播团队知道哪些句子可以直接说、哪些需要限定条件。
```

## B｜用户任务 + 可感知变化 + Message Ladder
```text
对每个核心技术建立【Message Ladder】：
技术机制 → 产品能力 → 用户场景 → 用户可以感知的变化 → 最终结果 → 证明方式。

再按人群做深度分层：
- 普通用户：我能得到什么；
- 核心/专业用户：为什么能做到；
- 媒体/creator：什么事实值得讲；
- 销售/体验顾问：怎样演示和回答问题；
- 合作伙伴/企业客户：对系统/业务意味着什么。

提炼 3 个最重要用户问题和 3 个最常见误解，给准确、自然、不过度简化的回答。

成功标准：用户价值与技术事实之间有可追溯链路，没有从“参数”直接跳到夸张好处。
```

## C｜10 秒 / 1 分钟 / 5 分钟三层表达
```text
基于同一事实源生成三种深度：
【10 秒】一句普通用户能理解、仍然准确的话；
【1 分钟】媒体/creator 可复述，包含原理 + 用户变化 + Proof；
【5 分钟】专业用户能理解机制、优势、测试条件、边界和适用场景。

如使用比喻/类比：先说明它帮助理解哪一点，再检查哪里可能误导；必要时补一句准确解释。

分别给中文和英文核心表达（若题目涉及海外），英文优先自然可说，不逐字翻译中文结构。

成功标准：不同深度表达结论一致，越短越简单但不篡改事实。
```

## D｜Proof Design：让技术差异被看见
```text
为最重要的 1–3 个技术差异设计至少四类证明候选：
现场 Demo / 前后或竞品对比 / 数据可视化 / 第三方或真实用户证据。

比较它们的：可信度、可感知性、耗时、可重复性、现场稳定性、拍摄传播性、成本和风险，推荐最合适组合。

每个 Demo 写【Demo Script】：
1）用户先遇到什么问题；
2）输入条件；
3）用户做什么；
4）系统发生什么；
5）观察结果；
6）20 秒讲解；
7）测试边界；
8）异常/失败备用方案；
9）如何拍成短视频/媒体素材。

成功标准：用户尽量自己看到/听到/操作到差别；同一 Demo 可被门店、展会、媒体和内容复用。
```

## E｜资产系统 + FAQ + 误读防护
```text
把同一技术证据转成一套统一资产：
一张对比图 / 15 秒短视频 / 60 秒解释 / 详情页模块 / 媒体事实卡 / 销售 Demo / 展会讲解 / FAQ / 客服回答。

建立“事实核心 + 渠道表达”表，确保所有资产共享同一参数、限定条件和比较对象。

FAQ 至少覆盖：为什么需要它、与现有方案区别、适用/不适用场景、隐私/安全、兼容、性能边界、价格价值、常见误解。

最后做【误读扫描】：哪些标题/比喻/数字最可能被媒体或用户断章取义？给更稳妥的表达。

成功标准：用户能复述价值，媒体能准确引用，技术团队认可边界，现场能稳定演示，多个渠道之间不会出现不同“事实版本”。
```

## 注意避免
- 把实验室峰值写成所有场景体验；
- 技术名词堆很多，但用户仍不知道能得到什么；
- 为了“简单”把条件和限制删掉；
- 只有动画/视频，没有能验证的 Proof；
- 用类比制造了错误技术理解；
- 详情页、媒体稿、销售话术出现不同参数口径。
