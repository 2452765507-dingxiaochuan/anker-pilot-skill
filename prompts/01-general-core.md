# 01｜任意题型通用主干（4 个 Prompt）

> 先把问题做对，再谈岗位专业。任何题型都可以从这里开始。

## 1｜启动 + 审题 + 任务拆解

```text
你现在是我的高级业务问题解决搭档。

不要预设这是一道品牌、营销、产品、运营或技术题。先根据题目本身判断，它真正属于什么问题、需要哪些专业能力。

请完整阅读我提供的题目、附件、数据、用户反馈和其他材料。先不要给最终方案。

请依次完成：
1）用你自己的话说明：题目真正要求解决什么；最终必须交付什么；成功标准是什么；有哪些明确约束。
2）区分四类信息：
- 【已知事实】题目明确提供；
- 【已有资料】知识库或数据库可以支持；
- 【缺失信息】目前没有但可能影响判断；
- 【工作假设】为了继续分析暂时建立、仍需验证。
3）找出决定结果的 3–5 个核心问题。不要为了完整罗列十几个问题，要判断真正重要的是什么。
4）按“先解决什么、后解决什么”设计接下来的工作路径。互不依赖的任务可以建议并行。
5）最后输出一份简洁的【任务单】：核心目标、核心问题、硬性要求、关键约束、待验证问题、下一步。

如果你发现我对题目的理解有问题，请直接指出。
```

## 2｜证据补充 + 深入诊断

```text
现在不要急着想方案。围绕上一阶段确定的核心问题，先判断“我们到底缺什么证据”。

请先提出最值得验证的 3–5 个关键假设。针对每个假设说明：
- 为什么值得验证；
- 已有什么证据；
- 还缺什么信息；
- 如果这个假设错误，会怎样改变我们的方案。

需要外部资料时再联网搜索，不要为了显得研究充分而宽泛搜索。搜索优先级：
①官方/一手资料；②权威行业资料；③高质量媒体/研究机构；④用户评价、社区和案例作为补充。

重要事实注明来源与时间，并严格区分：【已证实】【较强推断】【工作假设】【仍未知】。

分析完成后，不要只总结信息，请回答“所以真正的问题是什么？”
输出：
1）最重要的 3–5 个发现；
2）每个发现背后的证据；
3）每个发现意味着什么【So What】；
4）最值得解决的根因；
5）哪些原来的判断应该被推翻。
```

## 3｜形成策略 + 做出选择

```text
基于已经确认的事实和诊断，现在进入方案阶段。

不要马上给一个看似完整的标准答案。先提出 3 条明显不同的解决路径：
A｜相对稳妥；
B｜更有突破性；
C｜在资源有限情况下效率最高。

每条说明：核心逻辑、解决哪个根因、用户价值、业务价值、所需资源、主要风险、最适合什么条件。

然后用同一套标准比较，最后必须明确告诉我：你推荐哪一条，为什么。不要把最终选择重新丢给我。

在推荐方案基础上形成完整方案：
- 核心策略；
- 关键动作与优先级；
- 时间节奏；
- 谁负责；
- 需要什么资源；
- 如何衡量；
- 最大风险；
- 什么情况下需要调整或停止。

最终让我看到的是：为什么这样做 → 做什么 → 怎么做 → 怎么知道做对了。
```

## 4｜设计最终交付物

```text
现在策略已经确认。请重新读取题目对最终交付物的要求，再决定应该制作什么，不要默认制作网页。

可能包括：【方案文档】【HTML / Demo】【数据看板】【流程图】【内容样稿】【传播素材】【其他题目明确要求的形式】。

先输出：
1）最终交付清单；
2）每个交付物解决什么问题；
3）内容结构；
4）还缺哪些素材或数据。

确认结构后再制作。

制作原则：
- 信息层级优先服务于判断与阅读，设计技巧只在能提升理解时使用；
- 不编造数据；没有数据就明确标注；
- 图表只有在帮助理解时才使用；
- 页面设计必须来自题目内容与品牌特征，不套默认科技 Dashboard；
- 每个交付物都应该能被业务方直接使用。
```

## 随时可用｜纠偏

```text
请再检查一下刚才这个判断。先列出它依赖的前提，区分已有证据与推断，并尝试至少一种可能的替代解释。如果核心前提发生变化，请重新推导结论，并说明为什么调整或保留原判断。
```

## 长对话可用｜阶段总结

```text
请把目前已经确认的内容压缩成一页【阶段总结】：题目与目标、已确认事实、最重要发现、已经否定的方向、当前选择及理由、仍存在的假设、最大风险、尚未解决的问题、下一步 3 个动作。不要补新内容。
```
