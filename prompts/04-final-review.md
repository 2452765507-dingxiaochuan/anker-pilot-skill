# 04｜最终审查与提交（2 个 Prompt）

## 1｜多视角压力测试 + 优化
```text
现在暂时停止扩写。请用一次建设性的【多视角压力测试】帮助方案变得更扎实。

依次站在：目标用户、业务负责人、财务负责人、品牌负责人、执行团队、合作伙伴/媒体、法务与合规的角度，判断：
- 哪些地方已经有充分依据，可以保留；
- 哪些地方仍需要补证据或写清前提；
- 哪些动作在现实执行里可能遇到阻力；
- 有哪些更简单、更高效或更有体验感的替代做法；
- 哪些风险值得提前设置观察指标与调整触发点。

每个重要问题输出：
【观察】/【影响】/【建议优化】/【需要验证的证据】/【调整触发信号】。

重点挑真正影响结果的事项，不为凑数量找问题。完成后直接把成立的优化写回方案，并保留已经证明合理的部分。
```

## 2｜事实验证 + 最终交付检查
```text
现在进入提交前检查。请用证据决定能否提交。

重新读取：①原始题目 ②交付要求 ③当前方案 ④当前文件。

【要求覆盖】
逐条编号题目要求，并指出它在最终成果中的对应位置。

【事实】
核对数字、产品参数、市场数据、案例和引用。明确区分【题目事实】【安克资料】【外部事实】【工作假设】【派生计算】。对任何仍无法确认的数字进行删除、降级或明确标注。

【逻辑】
检查关键结论是否由证据支持；检查策略、动作、指标之间是否能互相对应；补齐必要前提。

【执行】
检查负责人、时间、资源、依赖、衡量方式和调整信号是否明确。

【文件】
如果有 HTML / Demo：实际打开，点击主要交互，检查图表、链接、常见窗口宽度；搜索 TODO、TBD、placeholder、xxx、NaN、undefined、未替换【】等残留。

【文字与视觉】
删除重复和模板化表达；检查信息层级、图表是否真的帮助理解；确认视觉风格与题目和品牌一致。

最后输出：
1）本轮实际检查动作与结果；
2）已完成的修改；
3）仍未解决的事项；
4）题目要求逐项对应表；
5）最终文件清单；
6）明确结论：可以提交 / 需要先修正哪些事项。
```
