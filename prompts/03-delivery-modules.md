# 03｜交付物模块（题目需要什么才调用什么）

## A｜HTML / Demo｜设计与实现一体化
```text
题目需要可打开的 HTML / Demo。核心策略已经确认，现在把它转成高质量视觉交付。

【先做 Design Brief】
在写代码前先输出：
- 主要受众；
- 页面最重要的业务任务；
- 用户 30 秒内必须理解的 3 件事；
- 信息阅读顺序；
- 一套明确的视觉方向（3–5 个形容词 + 为什么适合本题）；
- 关键视觉母题/图形语言；
- 哪些内容适合图表、时间轴、流程、地图、卡片或纯文字。

视觉来自具体题目和品牌内容。可以参考高水平商业提案与产品网站的精度，但不要套“科技蓝渐变 + KPI 四卡 + 所有区块圆角卡片”的默认 AI 页面。

【实现原则】
- 单文件优先，稳定性优先；
- 如果外部 CDN 失败，核心信息仍可读；
- 首屏直接给核心判断/概念，不放空洞 Hero 文案；
- Typography、留白、网格、对齐比装饰更重要；
- 每种组件只在有明确内容作用时出现；
- 图表标题直接写结论，并注明数据来源/示意状态；
- 交互不追求数量，优先帮助比较、切换、理解和浏览；
- 页面需要适配常见笔记本窗口和窄屏；
- 所有数字只来自题目、知识库或已查证来源。

【完成后设计审查】
分别以“业务负责人 / 高级视觉设计师 / 第一次看方案的人”浏览一次：
1）最重要的内容是否最先被看到；
2）有没有模板化、重复的卡片结构；
3）颜色、字体、图表是否在表达同一个视觉系统；
4）有没有为了炫技增加阅读成本；
5）页面是否具有与本题相匹配的独特性。

最后实际打开页面、点击主要交互、检查控制台/链接/布局/占位符，再汇报完成情况。
```

## B｜方案文档 / 提案｜结论先行 + 业务可执行
```text
题目需要一份业务方案或提案。请把已经确认的分析整理成业务负责人可以快速判断并继续执行的版本。

推荐结构：
执行摘要 → 目标与约束 → 证据与洞察 → 关键判断 → 推荐策略 → 核心机制/方案 → 执行路线 → 资源与责任 → 指标与学习 → 风险与调整信号 → 附录与来源。

每一章开头先给结论，再给证据和推导。图表/表格只在能缩短理解时间时使用。

最终进行一次编辑：
- 保留事实、限定条件、明确判断；
- 删掉重复的背景、万能行业趋势、空洞形容词；
- 把“提升品牌影响力”等模糊表达改成具体用户变化或业务结果；
- 句子和段落保持自然节奏；
- 专业词只在提高精度时使用，并保证普通业务读者能理解。
```

## C｜数据看板 / 分析页｜围绕决策组织
```text
先问：业务方打开这个看板要做哪几个决定？

只保留支持这些决定的指标，并给每个指标写：定义、来源、更新频率、正常/异常判断、出现异常后采取什么动作。

每个图表都写一个结论型标题，例如“亚马逊占比下降，但仍是最大单一渠道”，避免只写“渠道占比”。

看板至少区分：结果指标、过程指标、预警指标。支持从总览快速下钻到原因，但避免一屏塞满所有数据。
```

## D｜视觉/内容样稿｜先立一个强母版再扩展
```text
如果题目要求 KV、社媒样稿、落地页文案、脚本或内容示例，先做一个最强母版并说明：目标受众、核心信息、视觉/语言方向、证据和 CTA。

母版通过后，再扩展不同平台/尺寸/语种。保持战略核心一致，但允许表达、节奏和版式适应具体渠道。

最终同时检查事实、品牌、平台规范、语言自然度与视觉一致性。
```
