0A｜Claude 高性能作战模式

可复制
接下来进入【高性能作战模式】。不需要节省 token；优先追求正确、深入、快速并行和最终完成度。

【1｜先判断任务结构】
先把任务拆成：
- 必须串行完成的关键判断；
- 可以并行调查的独立问题；
- 最后统一整合的部分。
优先把互不依赖的任务并行；存在依赖关系的判断保持串行，并给不同窗口清晰边界以减少重复。

【2｜并行研究时给每个任务清晰边界】
每个独立研究任务都要写清：
- 它要回答的具体问题；
- 已知上下文；
- 必须优先看的来源；
- 不需要研究什么；
- 最终只返回哪些结果。

建议研究任务统一返回：
① 关键发现；② 证据/来源；③ 置信程度；④ 对本题意味着什么；⑤ 仍然缺什么。
这样主窗口只接收高密度结果，不接收冗长过程。

【3｜先形成判断，再定向检索】
先建立少量关键假设和证据缺口，再去联网检索。
检索围绕关键假设与证据缺口展开，优先保证每次搜索都能影响判断。
如果多个来源冲突，记录口径、时间与来源等级，再决定采用哪一个。

【4｜阶段性压缩上下文】
每完成一个重要阶段，把结果压成一页【阶段快照】：
- 已确认事实；
- 当前判断；
- 已放弃方向及原因；
- 仍未验证的假设；
- 下一步。
后续优先引用阶段快照，避免反复重新阅读全部对话。

【5｜创意与方案先发散、再收敛】
需要创意时，先给 3–5 个真正不同的方向；每个方向说明洞察、机制、品牌资格和可执行性。
随后使用同一套标准比较并明确推荐，不把选择留给我。

【6｜视觉交付】
需要 HTML / Demo / 页面时，先确定：
- 谁看；
- 页面最重要的任务；
- 希望留下什么感受；
- 信息层级；
- 一套明确的视觉方向。
让视觉来自题目、品牌和内容本身。优先发展独特的信息层级与审美方向，减少“科技蓝渐变 + 四张 KPI 卡 + 通用 Dashboard”等默认模板。
每个图表、动效、卡片都必须有信息作用。

【7｜文字质量】
最终文案进行一次自然语言编辑：
- 保留所有事实、限定条件和作者判断；
- 删除重复、空话、套话和为了完整而写的铺垫；
- 句子长短有变化；
- 专业术语只在确实提高精度时使用；
- 自然化处理保留必要逻辑、事实与限定条件；
- 减少对抗式反驳句，优先直接说建议、可能性、取舍与注意事项。

【8｜完成前必须验证】
任何“已经完成/可以提交”的判断前，都先找到能证明它的检查动作并实际执行：
- 重新核对题目要求；
- 重新核对关键事实；
- 实际打开 HTML / 文件；
- 点击主要交互；
- 搜索占位符、未替换字段和错误；
- 检查关键数字和结论。

完成后基于检查结果报告实际状态，重点说明已通过项和仍需处理项。

1｜启动 + 审题 + 任务拆解

可复制
你现在是我的高级业务问题解决搭档。

不要预设这是一道品牌、营销、产品、运营或技术题。先根据题目本身判断，它真正属于什么问题、需要哪些专业能力。

请完整阅读我提供的题目、附件、数据、用户反馈和其他材料。先不要给最终方案。

请依次完成：
1）用你自己的话说明：题目真正要求解决什么；最终必须交付什么；成功标准是什么；有哪些明确约束。
2）区分四类信息：
- 【已知事实】题目明确提供；
- 【已有资料】知识库或数据库可以支持；
- 【缺失信息】目前没有但可能影响判断；
- 【工作假设】为了继续分析暂时建立、仍需验证。
3）找出决定结果的 3–5 个核心问题。不要为了完整罗列十几个问题，要判断真正重要的是什么。
4）按“先解决什么、后解决什么”设计接下来的工作路径。互不依赖的任务可以建议并行。
5）最后输出一份简洁的【任务单】：核心目标、核心问题、硬性要求、关键约束、待验证问题、下一步。

如果你发现我对题目的理解有问题，请直接指出。

2｜证据补充 + 深入诊断

可复制
现在不要急着想方案。围绕上一阶段确定的核心问题，先判断“我们到底缺什么证据”。

请先提出最值得验证的 3–5 个关键假设。针对每个假设说明：
- 为什么值得验证；
- 已有什么证据；
- 还缺什么信息；
- 如果这个假设错误，会怎样改变我们的方案。

需要外部资料时再联网搜索，不要为了显得研究充分而宽泛搜索。搜索优先级：
①官方/一手资料；②权威行业资料；③高质量媒体/研究机构；④用户评价、社区和案例作为补充。

重要事实注明来源与时间，并严格区分：【已证实】【较强推断】【工作假设】【仍未知】。

分析完成后，不要只总结信息，请回答“所以真正的问题是什么？”
输出：
1）最重要的 3–5 个发现；
2）每个发现背后的证据；
3）每个发现意味着什么【So What】；
4）最值得解决的根因；
5）哪些原来的判断应该被推翻。

3｜形成策略 + 做出选择

可复制
基于已经确认的事实和诊断，现在进入方案阶段。

不要马上给一个看似完整的标准答案。先提出 3 条明显不同的解决路径：
A｜相对稳妥；
B｜更有突破性；
C｜在资源有限情况下效率最高。

每条说明：核心逻辑、解决哪个根因、用户价值、业务价值、所需资源、主要风险、最适合什么条件。

然后用同一套标准比较，最后必须明确告诉我：你推荐哪一条，为什么。不要把最终选择重新丢给我。

在推荐方案基础上形成完整方案：
- 核心策略；
- 关键动作与优先级；
- 时间节奏；
- 谁负责；
- 需要什么资源；
- 如何衡量；
- 最大风险；
- 什么情况下需要调整或停止。

最终让我看到的是：为什么这样做 → 做什么 → 怎么做 → 怎么知道做对了。

可复制

1）最终交付清单；

- 每个证据对用户意味着什么【Human Payoff】；

再发展核心创意【Big Idea】。至少提出 3 个真正不同的方向，每个方向都写清：
- 来自什么用户洞察或文化情绪；
- 为什么这个品牌有资格讲；

- 如何延展到内容、活动、社媒、媒体与线下；
- 哪部分最有记忆点；
- 容易落入俗套的地方，以及如何优化。

随后设计传播路径：注意 → 理解 → 相信 → 行动 → 分享/留存。
每一步说明：用户状态、传播任务、最合适的内容、渠道、表达主体、所需证据和下一步行为。

渠道选择必须回答“它在这一步具体完成什么任务”，形成互相接力的系统。

3｜传播运营系统 + 专业审稿

可复制
现在把传播方向变成可以运行和复盘的系统。

【内容体系】
建立核心母内容、证明内容、场景内容、社交参与内容、转化内容、长期沉淀内容之间的关系。说明哪些素材可以复用、哪些必须为平台重新创作。

【媒体与创作者】

【节奏】
把项目拆成用户状态变化的阶段。对每阶段说明：要解决什么、主要动作、进入下一阶段的信号、效果偏低时优先调整什么。

【预算】

  • 全球统一素材直接翻译，忽略当地购买习惯和 creator 语言；

对同一目标生成少量真正不同的变体，并明确每个变体在测试什么假设。数据回来后只把有效学习沉淀进下一轮，不追求无限变体。

最终输出内容日历 + 资产清单 + 版本号 + 审核状态 + 指标 + 学习记录。

E｜效率与质量成功标准

可复制
用“速度、质量、品牌一致性、可追溯性、复用率”五个维度验收 AI 内容系统。可以计算：Brief→发布周期、一次通过率、返工率、母资产复用率、本地化周期、错误率、内容表现。

如果只有“写得更快、数量更多”，但审核更累或品牌更乱，说明流程仍需调整。
注意避免
  • 一开始就批量生成，错误被规模化；
  • 把“多平台适配”做成同一母稿机械缩写；
  • AI 视觉改变真实产品外观、接口、尺寸或 Logo；
  • 本地化只有直译，没有当地平台、文化、单位、价格和禁忌适配；
  • 只统计产量和速度，不测返工率、事实错误和品牌一致性；
  • 为了去 AI 味改动事实、确定程度或技术限定条件。

整合营销 / 品牌战役

A｜案例迁移 + 战役机会判断

可复制
先读取整合营销案例包，只提取与本题最相关的 3–4 个机制，不复述案例历史。

建立【战役机会地图】：
- 当前业务需要改变什么；
- 用户此刻有什么真实情绪、行为或文化张力；
- 品牌凭什么参与这个话题【Brand Right to Play】；
- 产品/技术有什么可以被证明的真实证据；
- 为什么是现在；
- 哪些社会/平台/节日/文化时刻可以成为放大器。

提出 3 个明显不同的机会区。每个机会区必须包含：
1）一句用户张力；
2）品牌扮演的角色；
3）最强产品/品牌证据；
4）用户为什么愿意注意或参与；
5）可形成的内容/事件；
6）能留下什么长期资产；
7）执行难点和不适用条件。

用【相关性、独特性、可参与性、可证明性、可延展性、执行难度、长期资产】同一套标准比较，并明确推荐一个。

成功标准：战役机会来自真实用户/文化张力与品牌资格的交集，主题和形式在此基础上自然生长。

B｜Big Idea + 参与机制 + Campaign Architecture

可复制
把选定机会发展成 3 个不同的【Big Idea】方向，再选择一个继续深入。

每个方向必须回答：
- 用户最终记住什么；
- 用户可以主动做什么、参与什么、表达什么；
- 品牌/产品为什么自然存在；
- 哪个画面/行为/符号能成为记忆锚点；
- 是否能跨 15 秒短视频、长内容、线下、媒体、零售和社媒继续生长。

选定后建立【Campaign Architecture】：
Hero：核心事件/内容/高点；
Hub：持续内容与用户承接；
Proof：产品、技术、第三方或真实体验证明；
Participation：用户/creator 如何参与和二创；
Conversion：官网、电商、门店、会员等业务承接；
Legacy：战役结束后留下什么品牌资产、用户资产、内容资产或组织方法。

同时输出一张“核心信息—关键证据—主要内容—渠道—CTA”关系表，避免各渠道各讲各的。

成功标准：一句话能说清创意，用户参与机制简单可懂，产品证据自然嵌入，所有模块围绕同一个核心思想。

C｜渠道接力 + Creator / Media / Experience 分工

可复制
现在设计完整传播接力，不做渠道清单。

按用户状态拆阶段：
尚未注意 → 愿意停留 → 理解 → 相信 → 参与/讨论 → 行动 → 分享/复访。

对每个阶段明确：
- 用户还缺什么；
- 最重要的信息/证据；
- Owned / Earned / Creator / Paid / Experience / CRM 分别承担什么任务；
- 内容格式；
- CTA；
- 进入下一阶段的信号。

Creator 进一步分为：专业解释者、生活方式使用者、文化参与者、转化型、真实用户。说明各自为什么可信、Brief 自由度、必须保留的证据和验收方式。

媒体部分给 3–5 个新闻切口，说明哪些能形成 earned media，哪些更适合品牌自有内容。

成功标准：每个渠道都有独立职责，前后能接力；减少“所有平台同步发同一条物料”的低效做法。

D｜资产工厂 + 执行节奏 + 预算逻辑

可复制
把战役变成可以执行和复用的【传播资产工厂】。

列出：Hero Film/主视觉、短视频母素材、产品 Proof、媒体资料包、creator Brief、UGC 模板、FAQ、零售/电商素材、CRM 素材、销售工具、案例复盘、用户洞察等。

对每类资产说明：
- 谁生产；
- 最晚何时完成；
- 依赖哪些上游信息；
- 可以被哪些渠道复用；
- 哪些渠道必须重新创作而不能简单裁切。

给完整时间轴：准备 → 预热 → 引爆 → 持续 → 长尾。标出关键依赖、审批节点、素材锁定日和备用方案。

预算不要机械平均分配。先说明最大预算应该解决哪一个核心瓶颈，再按内容制作、creator、媒体/公关、付费放大、体验/活动、技术/页面、监测和预备金给分配逻辑。

成功标准：团队能直接从时间轴和资产表开始执行；资源优先级与核心问题一致。

E｜衡量 + 学习 + 最终交付验收

可复制
建立六层指标：
1）文化/讨论：话题是否进入真实讨论；
2）内容质量：完播、保存、深度互动、有效评论；
3）品牌：认知、理解、信任、偏好、搜索；
4）参与：UGC/creator 参与、活动参与、复访；
5）业务：访问、线索、转化、销售、会员；
6）资产：可复用素材、媒体关系、用户洞察、长期内容系列。

每个指标写清：如何采集、它回答什么决策问题、什么趋势说明加码/调整/停止。

设计战役中的 3–5 个学习点，例如：核心主张、creator 类型、Proof、参与机制、首屏/CTA，并说明如何用数据改变下一阶段。

最终方案必须让评审一眼看到：机会洞察 → Big Idea → 参与机制 → 渠道接力 → 资产与执行 → 预算 → 指标 → 长期资产。

最后做一次完整性检查：如果删掉 Logo，创意是否仍然与品牌/产品高度相关？如果用户不参与，是否仍有价值？如果某个平台失效，系统是否有替代路径？
注意避免
  • 追热点比用户问题更重要；
  • slogan 很漂亮，但没有参与机制和产品 Proof；
  • Paid / KOL / PR 只是并列预算项，没有用户路径；
  • 开幕/发布日过度投入，战役后一周就失去内容；
  • KPI 只有曝光和互动，没有品牌/业务变化；
  • 把其他品牌的视觉形式直接复制，而没有迁移机制。

A｜新闻价值地图 + 媒体分层

可复制
读取 PR 案例包和题目事实，先做【新闻价值地图】。

从以下方向判断哪些真正成立：
公司战略变化、行业趋势、技术/产品突破、用户影响、可验证数据、当地市场意义、人物故事、设计/体验、合作生态、公共议题。

B｜Message House + Media Kit + 发言人体系

可复制
建立媒体沟通【Message House】：
核心结论 / 3 个支撑信息 / 每个支撑的证据 / 对行业和用户意味着什么 / 需要保留的限定条件。

- 80–120 字事实摘要；
- 5–8 条可直接引用的事实点；
- 关键数据及来源；
- 产品/技术/人物/空间图片；
- Demo 视频或 B-roll；
- 时间线；
- 10–15 个 Q&A；
- 技术词汇表；
- 易误解表达及准确版本；
- 联系人与会后补充机制。

成功标准：媒体即使只使用资料包，也能写出事实准确、有行业意义的报道。

C｜发布会 / 媒体体验旅程

为什么值得来 → 到场后 5 分钟内理解什么 → 哪个 Demo 最能证明新闻点 → 谁讲什么 → 什么时候有采访 → 如何快速拿到素材 → 离场后怎样继续获得信息。

输出：
1）议程与每段的“新闻任务”；
2）空间/展区/体验设计；
3）最值得拍摄的 3–5 个视觉节点；
4）媒体分组与采访安排；
5）直播/社媒与现场关系；
6）资料发放和会后 follow-up；
7）技术故障、发言超时、临时质疑等备用方案。

每一个现场装置、视频和演讲段落都要对应一个报道信息点，并尽量让记者通过亲自体验获得证据。

成功标准：记者的时间被尊重；采访、拍摄、事实确认和素材获取都顺畅；现场体验能直接支持报道角度。

D｜Earned Media 运营 + 媒体关系资产

可复制
设计四阶段媒体运营：
会前预沟通 / embargo 或预览（如适用） → 发布日 → 会后深度 → 长尾行业议题。

建立媒体名单逻辑：Tier 1 / 垂直核心 / 本地 / creator / 分析师，各自的价值、关系目标、pitch 内容和 follow-up 频率。

建立媒体问答与快速响应机制：哪些问题可以现场回答，哪些需要研发/法务确认，承诺多久补充。

衡量不要只看发稿量。至少看：
目标媒体覆盖、核心信息带出率、事实准确率、独立观点/引用、正负面、Share of Voice、搜索结果、后续采访、媒体关系深度和内容二次引用。

成功标准：活动结束后仍有可持续媒体议题和关系资产，而非只完成一轮新闻稿分发。

E｜编辑视角验收

可复制
最后模拟三名目标媒体编辑：商业财经、科技产品、生活方式。

每人只基于当前资料写：
- 一个可能采用的标题；
- 5 行报道摘要；
- 还缺的事实；
- 最想追问的一题；
- 哪一处最像品牌宣传、需要补证据或换表达。

根据结果修订 Media Kit、发言人 Q&A 和现场安排。

最终产出应包含：新闻价值地图、媒体分层、Message House、Media Kit、Q&A、发布会旅程、媒体运营时间轴、指标和风险处理。

  • 发布会大部分时间被 PPT 占用，Demo/采访时间不足；
  • 用“发稿量”代替真正媒体影响；
  • 对未确认技术/安全问题过度承诺。

A｜数据诊断 + 平台角色

可复制

B｜内容世界观 + 支柱 + 系列化栏目

可复制
读取案例包，提取 2–4 个可迁移机制：稳定 persona、系列化 lore、用户身份分享、creator 共创、平台原生语言等。

设计 3–5 个长期内容支柱。每个支柱写：
用户需求 / 品牌价值 / 产品连接 / 主要格式 / 可持续素材来源 / 更新频率 / 成功信号。

把支柱发展成可连续追看的【栏目/角色/规则/仪式】：
- 用户为什么知道“下次还会发生什么”；
- 哪些元素长期稳定；
- 哪些元素可以随热点/新品变化；
- 如何让产品以自然、必要的方式进入内容。

至少生成 10 个具体选题，但要标明它们分别服务哪个支柱和用户状态。

成功标准：账号有稳定识别和连续性，单条内容即使不爆，也能积累品牌记忆与用户关系。

C｜Creator / UGC / Paid 放大系统

可复制
建立 creator 角色地图：
专业解释者 / 科技测评 / 生活方式 / 文化参与 / 转化型 / 真实用户 / 员工专家。

对每类说明：适合解决什么问题、为什么可信、内容自由度、必须保留的事实、最适合的 KPI、合作与复用方式。

设计 Creator Brief：核心任务、受众、必须传达的 Proof、可自由发挥空间、禁区、素材/产品支持、交付格式和审核方式。避免把所有 creator 写成同一种脚本。

UGC 机制优先寻找用户愿意表达的：身份、成果、选择、审美、习惯、挑战结果、生活改善。说明参与门槛、示例、激励、品牌如何精选/二创。

Paid 只放大已经被自然数据验证或有明确任务的内容。说明什么时候使用 Spark/白名单/再营销/站外引流，以及放大的学习目标。

成功标准：creator 和 UGC 能形成真实多样性，同时核心证据保持一致。

D｜增长循环 + 评论/搜索运营 + 数据学习

可复制
建立增长循环：
洞察 → 选题 → 制作 → 发布 → 评论/搜索 → 二创 → creator/UGC → 转化/会员 → 用户反馈 → 下一轮。

把评论区作为产品和传播研究：按“疑问、反对、使用场景、购买障碍、功能请求、情绪、竞品比较”分类，给响应原则和可以回写到 FAQ/详情页/产品团队的内容。

建立周/月复盘：
- 继续什么；
- 停止什么；
- 扩大什么；
- 下个月测试什么。

每一环只保留 1–2 个真正能驱动决策的指标。给出实验日志模板：假设 / 内容变体 / 数据 / 结论 / 下一步。

成功标准：账号持续变聪明，内容数据能够反向影响选题、产品表达和用户运营。

E｜最终产出与成功控制

可复制
最终输出应包含：账号诊断、平台角色、内容支柱、系列栏目、30 天样例日历、creator 体系、UGC 机制、评论/搜索运营、Paid 放大原则、指标与实验机制。

用四个维度验收：
1）识别度：用户能否认出“这是 Anker 会发的内容”；
2）持续性：团队是否能稳定生产 3 个月以上；
3）关系：用户是否愿意评论、关注、参与和回来；
4）业务：是否有清晰路径进入搜索、官网、电商、会员或线下体验。

避免用单个爆款或单纯粉丝增长作为唯一成功标准。
注意避免
  • 每个平台复制同一条视频；
  • 天天追热点却没有品牌连续性；
  • creator 只按粉丝量分层；
  • UGC 机制要求用户替品牌打广告；
  • 评论区只做客服，不沉淀洞察；
  • 为追求“人设”损害产品事实与品牌可信度。

A｜事实中心 + 风险分级 + 前 2 小时动作

可复制
先建立唯一事实中心【Single Source of Truth】。只写：
- 已确认事实；
- 尚未确认；
- 信息来源和时间；
- 受影响对象/范围；
- 潜在安全、隐私、法律、业务影响；
- 谁负责继续验证；
- 下一次更新时间。

按“伤害严重度 × 扩散速度 × 不确定性 × 可逆性”做风险分级。

随后给前 30 分钟 / 2 小时 / 24 小时行动清单，分别覆盖：停止继续风险、用户指引、内部升级、证据保存、客服、渠道/平台、监管/合作方沟通、公开信息占位。

每个动作写负责人和触发条件。

成功标准：团队先降低真实风险，并让用户清楚下一步，不因为急于发声明而放大错误信息。

B｜利益相关者回应 + 信息节奏

可复制
分别为：受影响用户、普通用户、员工、客服、媒体、零售/渠道伙伴、平台、监管/合作伙伴建立沟通表。

每类回答：
他们此刻最担心什么 / 我们已知道什么 / 他们需要采取什么行动 / 哪些信息暂不能确认 / 通过什么渠道 / 下一次更新时间。

公开表达建议使用：
事实 → 当前行动 → 对受影响者的帮助/补救 → 调查/验证 → 下一次更新。

生成：首份 holding statement、FAQ、客服话术、内部员工通知、媒体 Q&A。保持事实核心一致，但允许细节按对象变化。

成功标准：不同渠道不打架；用户能找到行动信息；对未知部分明确写“正在确认 + 下一次更新时间”。

C｜调查证据 + 第三方验证 + 更新机制

可复制
设计调查和证据计划：研发/质量检查、批次/日志、用户样本、第三方实验/审计（适用时）、监管沟通、供应链追踪。

为每个关键争议点建立“什么证据才能改变当前判断”。

每次有新证据时：
1）更新事实中心；
2）判断是否改变用户行动建议；
3）同步 FAQ / 官网 / 社媒 / 客服 / 媒体；
4）记录版本与时间；
5）说明旧说法为何调整。

技术/安全争议需要第三方时，选择具有实际专业资格和可复查方法的机构，而非只做背书 Logo。

成功标准：信息越来越接近事实，所有渠道使用同一最新版本。

D｜补救设计 + 30/60/90 天信任恢复

可复制
把恢复计划落到可观察改变：
产品/流程整改、召回/更换/退款、客服资源、质量门槛、第三方验证、透明机制、员工/渠道培训、持续用户沟通。

给 30/60/90 天路线：每阶段必须完成的事实验证、用户补救、流程改变、公开证明和管理层复盘。

建立指标：投诉/退换趋势、客服解决率、重复问题率、负面主题变化、媒体语义、用户调查、复购/留存、整改完成率等。

说明什么结果代表可以逐步恢复常规传播，什么信号代表仍需继续整改或扩大处理。

成功标准：恢复来自真实产品/流程改变和可验证证据，传播负责让改变被理解。

E｜危机桌面推演 + 最终验收

可复制
对方案做一次桌面推演【Tabletop Exercise】：
情境 1：新证据显示影响范围扩大；
情境 2：媒体拿到与公司初始声明不一致的信息；
情境 3：一名高影响力用户发布负面实测；
情境 4：监管要求更严格行动；
情境 5：内部信息被提前泄露。

逐一写：谁决策、30 分钟内做什么、哪些信息更新、哪些渠道暂停、下一次用户通知是什么。

最终检查普通用户是否能在 20 秒内知道：发生了什么 / 我是否受影响 / 我现在该做什么 / 公司正在做什么 / 什么时候再更新。
注意避免
  • 在事实未确认前给绝对保证；
  • 只关注舆情热度，忽略安全/补救；
  • 多个部门各自发不同口径；
  • 更新时偷偷删除旧说法，不解释变化；
  • 在产品/流程没有改变前急于做“品牌修复 Campaign”；
  • 用第三方背书替代真实调查方法。

A｜技术事实地图 + 证据等级

可复制
先以工程/产品视角建立【技术事实地图】，暂时不做营销表达。

逐项记录：
技术名称 / 解决的技术问题 / 核心机制 / 输入输出 / 与上一代或替代方案的差异 / 可量化结果 / 测试条件 / 限制 / 安全隐私边界 / 来源。

所有“更快、更强、更智能、更安全、领先”等比较都要写清比较对象、场景和测试条件。

把证据分为：官方规格、实验/benchmark、第三方测试、真实用户数据、现场 Demo、工作假设。标出哪些可以公开传播，哪些需要研发/法务确认。

成功标准：技术团队阅读后认为准确；传播团队知道哪些句子可以直接说、哪些需要限定条件。

B｜用户任务 + 可感知变化 + Message Ladder

可复制
对每个核心技术建立【Message Ladder】：
技术机制 → 产品能力 → 用户场景 → 用户可以感知的变化 → 最终结果 → 证明方式。

再按人群做深度分层：
- 普通用户：我能得到什么；
- 核心/专业用户：为什么能做到；
- 媒体/creator：什么事实值得讲；
- 销售/体验顾问：怎样演示和回答问题；
- 合作伙伴/企业客户：对系统/业务意味着什么。

提炼 3 个最重要用户问题和 3 个最常见误解，给准确、自然、不过度简化的回答。

成功标准：用户价值与技术事实之间有可追溯链路，没有从“参数”直接跳到夸张好处。

C｜10 秒 / 1 分钟 / 5 分钟三层表达

可复制
基于同一事实源生成三种深度：
【10 秒】一句普通用户能理解、仍然准确的话；
【1 分钟】媒体/creator 可复述，包含原理 + 用户变化 + Proof；
【5 分钟】专业用户能理解机制、优势、测试条件、边界和适用场景。

如使用比喻/类比：先说明它帮助理解哪一点，再检查哪里可能误导；必要时补一句准确解释。

分别给中文和英文核心表达（若题目涉及海外），英文优先自然可说，不逐字翻译中文结构。

成功标准：不同深度表达结论一致，越短越简单但不篡改事实。

D｜Proof Design：让技术差异被看见

可复制
为最重要的 1–3 个技术差异设计至少四类证明候选：
现场 Demo / 前后或竞品对比 / 数据可视化 / 第三方或真实用户证据。

比较它们的：可信度、可感知性、耗时、可重复性、现场稳定性、拍摄传播性、成本和风险，推荐最合适组合。

每个 Demo 写【Demo Script】：
1）用户先遇到什么问题；
2）输入条件；
3）用户做什么；
4）系统发生什么；
5）观察结果；
6）20 秒讲解；
7）测试边界；
8）异常/失败备用方案；
9）如何拍成短视频/媒体素材。

成功标准：用户尽量自己看到/听到/操作到差别；同一 Demo 可被门店、展会、媒体和内容复用。

E｜资产系统 + FAQ + 误读防护

可复制
把同一技术证据转成一套统一资产：
一张对比图 / 15 秒短视频 / 60 秒解释 / 详情页模块 / 媒体事实卡 / 销售 Demo / 展会讲解 / FAQ / 客服回答。

建立“事实核心 + 渠道表达”表，确保所有资产共享同一参数、限定条件和比较对象。

FAQ 至少覆盖：为什么需要它、与现有方案区别、适用/不适用场景、隐私/安全、兼容、性能边界、价格价值、常见误解。

最后做【误读扫描】：哪些标题/比喻/数字最可能被媒体或用户断章取义？给更稳妥的表达。

成功标准：用户能复述价值，媒体能准确引用，技术团队认可边界，现场能稳定演示，多个渠道之间不会出现不同“事实版本”。
注意避免
  • 把实验室峰值写成所有场景体验；
  • 技术名词堆很多，但用户仍不知道能得到什么；
  • 为了“简单”把条件和限制删掉；
  • 只有动画/视频，没有能验证的 Proof；
  • 用类比制造了错误技术理解；
  • 详情页、媒体稿、销售话术出现不同参数口径。

交付模块

方案、HTML / Demo、数据看板、视觉与内容样稿

A｜HTML / Demo｜设计与实现一体化

可复制
题目需要可打开的 HTML / Demo。核心策略已经确认，现在把它转成高质量视觉交付。

【先做 Design Brief】
在写代码前先输出：
- 主要受众；
- 页面最重要的业务任务；
- 用户 30 秒内必须理解的 3 件事；
- 信息阅读顺序；
- 一套明确的视觉方向（3–5 个形容词 + 为什么适合本题）；
- 关键视觉母题/图形语言；
- 哪些内容适合图表、时间轴、流程、地图、卡片或纯文字。

视觉来自具体题目和品牌内容。可以参考高水平商业提案与产品网站的精度，但不要套“科技蓝渐变 + KPI 四卡 + 所有区块圆角卡片”的默认 AI 页面。

【实现原则】
- 单文件优先，稳定性优先；
- 如果外部 CDN 失败，核心信息仍可读；
- 首屏直接给核心判断/概念，不放空洞 Hero 文案；
- Typography、留白、网格、对齐比装饰更重要；
- 每种组件只在有明确内容作用时出现；
- 图表标题直接写结论，并注明数据来源/示意状态；
- 交互不追求数量，优先帮助比较、切换、理解和浏览；
- 页面需要适配常见笔记本窗口和窄屏；
- 所有数字只来自题目、知识库或已查证来源。

【完成后设计审查】
分别以“业务负责人 / 高级视觉设计师 / 第一次看方案的人”浏览一次：
1）最重要的内容是否最先被看到；
2）有没有模板化、重复的卡片结构；
3）颜色、字体、图表是否在表达同一个视觉系统；
4）有没有为了炫技增加阅读成本；
5）页面是否具有与本题相匹配的独特性。

最后实际打开页面、点击主要交互、检查控制台/链接/布局/占位符，再汇报完成情况。

B｜方案文档 / 提案｜结论先行 + 业务可执行

可复制
题目需要一份业务方案或提案。请把已经确认的分析整理成业务负责人可以快速判断并继续执行的版本。

推荐结构：
执行摘要 → 目标与约束 → 证据与洞察 → 关键判断 → 推荐策略 → 核心机制/方案 → 执行路线 → 资源与责任 → 指标与学习 → 风险与调整信号 → 附录与来源。

每一章开头先给结论，再给证据和推导。图表/表格只在能缩短理解时间时使用。

最终进行一次编辑：
- 保留事实、限定条件、明确判断；
- 删掉重复的背景、万能行业趋势、空洞形容词；
- 把“提升品牌影响力”等模糊表达改成具体用户变化或业务结果；
- 句子和段落保持自然节奏；
- 专业词只在提高精度时使用，并保证普通业务读者能理解。

C｜数据看板 / 分析页｜围绕决策组织

可复制
先问：业务方打开这个看板要做哪几个决定？

只保留支持这些决定的指标，并给每个指标写：定义、来源、更新频率、正常/异常判断、出现异常后采取什么动作。

每个图表都写一个结论型标题，例如“亚马逊占比下降，但仍是最大单一渠道”，避免只写“渠道占比”。

看板至少区分：结果指标、过程指标、预警指标。支持从总览快速下钻到原因，但避免一屏塞满所有数据。

D｜视觉/内容样稿｜先立一个强母版再扩展

可复制
如果题目要求 KV、社媒样稿、落地页文案、脚本或内容示例，先做一个最强母版并说明：目标受众、核心信息、视觉/语言方向、证据和 CTA。

建设性压力测试 + 事实 / 文件 / 页面实际检查

1｜多视角压力测试 + 优化

可复制
现在暂时停止扩写。请用一次建设性的【多视角压力测试】帮助方案变得更扎实。

依次站在：目标用户、业务负责人、财务负责人、品牌负责人、执行团队、合作伙伴/媒体、法务与合规的角度，判断：
- 哪些地方已经有充分依据，可以保留；
- 哪些地方仍需要补证据或写清前提；
- 哪些动作在现实执行里可能遇到阻力；
- 有哪些更简单、更高效或更有体验感的替代做法；
- 哪些风险值得提前设置观察指标与调整触发点。

每个重要问题输出：
【观察】/【影响】/【建议优化】/【需要验证的证据】/【调整触发信号】。

重点挑真正影响结果的事项，不为凑数量找问题。完成后直接把成立的优化写回方案，并保留已经证明合理的部分。

2｜事实验证 + 最终交付检查

可复制
现在进入提交前检查。请用证据决定能否提交。

重新读取：①原始题目 ②交付要求 ③当前方案 ④当前文件。

【要求覆盖】
逐条编号题目要求，并指出它在最终成果中的对应位置。

【事实】
核对数字、产品参数、市场数据、案例和引用。明确区分【题目事实】【安克资料】【外部事实】【工作假设】【派生计算】。对任何仍无法确认的数字进行删除、降级或明确标注。

【逻辑】
检查关键结论是否由证据支持；检查策略、动作、指标之间是否能互相对应；补齐必要前提。

【执行】
检查负责人、时间、资源、依赖、衡量方式和调整信号是否明确。

【文件】
如果有 HTML / Demo：实际打开，点击主要交互，检查图表、链接、常见窗口宽度；搜索 TODO、TBD、placeholder、xxx、NaN、undefined、未替换【】等残留。

【文字与视觉】
删除重复和模板化表达；检查信息层级、图表是否真的帮助理解；确认视觉风格与题目和品牌一致。

最后输出：
1）本轮实际检查动作与结果；
2）已完成的修改；
3）仍未解决的事项；
4）题目要求逐项对应表；
5）最终文件清单；
6）明确结论：可以提交 / 需要先修正哪些事项。
